# 独自ドミネーション／コンクエスト

`bf4_game_objectives.sma`が両モードを提供します。CS Flagsの実装コード・モデル・音声は使用しません。旧`csflags.sma`とConquest試作は参照用に残しますが、同時ロードは拒否します。実サーバーの動作確認は未実施です。

## モードと占領

| 項目 | ドミネーション | コンクエスト |
|---|---|---|
| モード設定 | `domination` | `conquest` |
| 拠点数 | 3 | 1〜7 |
| 復活先 | マップのT・CTスポーンから安全な地点 | 自軍基地／自軍所有かつ交戦中でない拠点の設定済み地点 |
| 初期チケット | 100 | 400 |

両モードとも敵拠点を中立化してから占領します。半径内かつ視線が通る生存者の人数差を使い、最大3人分で進行、同数は停止します。無人時の途中進行は保持します。単独で1段階10秒が初期値です。

拠点の過半数を保有すると2秒ごとに敵チケットを1減らします。死亡では未精算状態を記録し、再出撃成功時または切断時に死亡時のチームから1消費します。蘇生は消費しません。全拠点占領だけでは即勝利にせず、0チケットで敗北、同時0は引き分けです。これらの数値は調整用のCS向け初期値で、BF4公式値の実測結果ではありません。

両チームと最低人数が揃うまで待機します。開始後に片側不在・人数不足になると占領、減少、復活待機、試合時計を停止します。任意の時間制限到達時は残チケットで判定します。マップ全体の制限時間は別です。車両・分隊・司令官は追加していません。

## 導入手順

1. `rtk proxy python tools/build_plugins.py`でビルドし、`plugins-bf4-v2.ini.example`を参考に独自プラグインを登録します。兵科基盤とランクを先にロードし、旧CS Flagsと`bf4_game_conquest.amxx`を無効にします。
2. `configs/bf4/objectives.cfg`をサーバーへ配置し、`bf4_objective_mode`を設定します。既定値`off`では標準ルールに介入しません。
3. `de_dust`／`de_dust2`は[同梱の3拠点配置](OBJECTIVE_LAYOUTS.md)を使用できます。他のマップは`configs/bf4/objectives/layout.ini.example`を`<map>.ini`としてコピーし、実マップで測った座標を記入します。空の配置例をそのまま有効にしても開始しません。
4. マップを再読み込みし、`bf4_objective_status`とAMXXログで設定・配置の受理、人数待機、実行状態を確認します。

設定値の範囲は、チケット1〜100000、占領時間1〜600秒、復活待機1〜120秒、減少間隔0.25〜600秒、減少量1〜1000、試合時間0〜1440分、最低人数2〜最大プレイヤー数です。変更はマップ再読み込みで反映します。

## 拠点・復活地点の書式

```text
point <A..G> <x> <y> <z> <radius>
spawn <T|CT|BOTH> <base|A..G> <x> <y> <z> <yaw>
```

数値は整数です。座標は-32768〜32767、半径1〜1024、角度-360〜360。`bf4_objective_origin`を管理権限で実行すると現在の立ち位置・向きを整数で取得できます。床ではなく立っているプレイヤーの中心座標を使います。行頭・空白後の`;`／`#`はコメントです。

ID重複、不明な拠点参照、拠点から半径外の復活地点、長すぎる行、不正数値は配置全体を拒否します。既存マップのスポーンも読み込み、設定分と合わせて最大128地点です。基地は既存スポーンだけでも構いません。拠点復活を使う場合はその拠点に`spawn`行が必要です。

復活直前に所有・競合状態、予約チーム、人体サイズの地形・エンティティ衝突、周囲の味方64／敵256ユニットを再確認します。選択先を失った場合や安全な地点がない場合は待機し、`say /deploy`から基地を選び直せます。敵拠点へ強制復活しません。蘇生器による復活では位置を変更しません。

## 表示・運用・連携

標準CSの`sprites/laserbeam.spr`で拠点範囲を描画し、HUDにID・所有者・進行度・残チケットを表示します。追加の`sprites/bf4_ranks/conquest/point.spr`があればマーカーにも使用しますが、必須ではありません。独自プラグインのために旧CS Flagsアセットを導入する必要はありません。

管理権限`ADMIN_CFG`で`bf4_objective_start`（ラウンドを再初期化して試合リセット）、`bf4_objective_stop`（標準目標・設定を復元）、`bf4_objective_status`、`bf4_objective_origin`を使用できます。管理再開時は設置済み爆弾・設置アニメーションを旧ラウンドごと消去します。有効配置がある場合のみ標準目標フラグを無効化し、C4の標準攻撃と標準勝敗判定を抑止します。クレイモアと共有する`weapon_c4`の装備自体は止めません。試合終了後はReGameDLLのラウンド終了・再開を使って次の試合を待機します。

ランクは独自の占領・試合終了イベントを受け、保存キー`ctf_capture`／`ctf_win`を維持します。完了時に拠点内にいる勝者側へ占領報酬、勝利チームへ試合単位の報酬を付与します。中立化は報酬対象外です。旧CS Flagsの`csf_*`通知はランクで受けません。APIは`include/bf4objectives.inc`を参照してください。

## 検証

`rtk proxy python tools/test_all.py`で純粋Pawnルール・配置解析と、死亡／蘇生／再出撃／切断／報酬通知の本番関数をオフライン検証します。エンジン境界のmockは実サーバーの代替ではありません。

遅延した蘇生器の処理より先に通常再出撃が完了した場合、蘇生器側が生存者をもう一度再出撃させないガードを追加しています。人数不足で停止中でも、切断の精算によってチケット0になった場合は勝敗を確定します。

サーバーでは、両モードの占領競合・遮蔽、予約チーム変更後の復活、拠点喪失中の復活待機、蘇生器の併用、初回ゲーム開始・全滅・時間切れ・管理再開、XP再接続保存を確認してください。標準モデルの見え方や復活位置の地形安全性、実ReGameDLLのフック動作は未検証です。
