# CS Flags独自化の調査結果

2026-10-23。調査後に独自ドミネーション／コンクエストを実装し、オフライン検証を完了しました。実サーバーへの導入は未実施です。現在の仕様・導入は [OBJECTIVE_MODES.md](OBJECTIVE_MODES.md)、検証結果は [VERIFICATION.md](VERIFICATION.md) を参照してください。以下は調査時の経緯です。

## 確認された目的

CS Flagsは、BF4のドミネーション・コンクエストルールを実現するために利用していました。目標はCS Flagsの互換再実装ではなく、両モードの独自実装です。以下の互換版候補は当初の調査記録であり、最終方針ではありません。

共通の拠点状態・占領判定・イベント通知と、各モードのチケット・勝敗・復活ルールを分離する構成を提案します。旧CS Flagsの設定・イベントを新ルールへ無条件に引き継ぎません。特に占領、ラウンド勝利、試合勝利による報酬は、新しい勝敗の単位と対応を定めてから移行します。

既存の `bf4_game_conquest.sma` は試作として保全し、拠点表示などの利用可能な部分を確認します。今回の依頼によりConquestのルール実装も対象になりますが、車両・分隊などルール以外の追加を自動的に含めるものではありません。

次に、BF4標準ルールを再現の基準とし、チケット数・占領時間・拠点配置を設定可能にする範囲を確認します。標準値や占領・復活の詳細を未確認のまま既知の仕様として記載しません。

## 外部依存と現状

`csflags.sma`はcommonbullet製CS Flags 1.194を基にする外部プラグインです。ファイルの改名や著者名の変更だけで独自実装とは扱いません。旧ソースの出自・クレジットを保持し、新実装は別ファイルで作成します。

既存動作は、持ち運ぶ旗のCTFではなく固定拠点の占領です。最大5拠点を持ち、占領状態に応じた得点、全拠点占領、ラウンド・試合の勝利判定を備えています。

## 維持を検討する互換境界

| 境界 | 現行仕様・確認事項 |
|---|---|
| ランク連携 | `csf_flag_taken(id)`、`csf_round_won(team)`、`csf_match_won(team)`を`bf4_ranksystem.sma`が受信。勝利2種は別々に報酬を付与しているため、通知をまとめたり重複と決めつけたりしない。 |
| マップ配置 | `configs/csflags/<map>.cfg`を参照。配置形式と実運用ファイルの互換性は実装前に確認する。 |
| 運用設定 | `amx_csflags_*`の有効化、占領待ち時間、得点上限、勝利上限、全拠点勝利、標準目標除去、復活・凍結などを調査対象にする。 |
| 管理操作 | 停止・再開に伴うスコア、タスク、エンティティの寿命を明確にする。 |
| アセット | `models/csflags/csflags.mdl`と`csflags/`配下の音声を参照。コードの独自化とアセットの出自は別に扱う。 |

## 実装方針の候補

1. **互換版を別プラグインとして新規作成**：`bf4_system_flags.sma`で状態・判定・通知を分離し、旧設定・イベントを互換境界として維持。既存のゲームバランスを守りやすい方針です。
2. **BF4専用API・設定へ一括移行**：同じ占領ルールを独自APIへ移し、ランク側とマップ設定も移行。旧運用との互換対応が増えます。

当初は1を推奨していましたが、確認された目的により、両モードを独自実装する方針へ見直します。本番切替は別工程です。

## 独自版の検証要件

占領開始・中断・競合・中立化・奪取、死亡・切断・同一スロット再利用、得点と勝利通知の回数、停止・再開を検証します。状態遷移はオフラインで確認し、モデル表示・当たり判定・HUD・実マップの互換性はゲームサーバーで別に確認します。
